## Decisions Made

### Decision 1: Controller-Based API
**Choice:** Use ASP.NET Core Controllers (not Minimal API)
**Rationale:** Better organization, easier validation attributes, industry standard for auth

### Decision 2: Service Layer Pattern
**Choice:** Create AuthService for token generation
**Rationale:** Separation of concerns, testability, SOLID principles

### Decision 3: DTO Pattern
**Choice:** Separate request/response DTOs
**Rationale:** Don't expose Identity entities, control data flow, validation support

### Decision 4: Deferred Features
**Choice:** Move refresh tokens to P2, email confirmation to P2
**Rationale:** MVP focus on core auth flow, these are enhancements

## Key Insights

1. **Infrastructure Already Exists:** Significant JWT setup already done (Identity, JWT Bearer, DbContext). This accelerates implementation - only need endpoints and token generation service.

2. **Security First:** Password requirements already properly configured. Need to ensure JWT secret in User Secrets (dev) and secure config (prod).

3. **Clear Scope Critical:** Many auth features exist (refresh tokens, email confirm, password reset, 2FA, OAuth). Explicitly documenting what's OUT of scope prevents scope creep.

4. **Edge Cases Matter:** Identified 6 edge cases including concurrent registration, token expiration timing, invalid JWT format, SQL injection, empty input, DoS via long passwords.

5. **Testability:** Service layer and DTO pattern decisions enable comprehensive unit and integration testing.
